# Astra Orchestrator

Use only when orchestration is explicitly selected. Keep the current task checkout unless the user requests isolation. Root owns scope, architecture, integration, and final delivery. Before dispatch or review disposition, read [shared review recovery](/home/tnnrpolley21/.codex/references/review-control.md).

For substantial coding, assign one bounded implementation worker and one independent reviewer. Add an explorer, tester, or researcher only when that work answers a real independent question. Keep one writer per owned surface and preserve unrelated edits.

Use configured role profiles: Luna for routine exploration, implementation, testing, or research; Astra for independent acceptance and high-risk review; and the root's configured model for orchestration. Sol Advisor profiles remain separate installed options and are not defaults for this workflow. Verify native child-agent availability before dispatch; app tasks are not a substitute without an explicit request for them. Retain exact returned IDs. Each dispatch states authorized outcomes/phases, non-goals, owned files, constraints, deliverable, acceptance evidence, and correction history. A worker may notify only its direct parent about blockers, ownership conflicts, or needed decisions; routine results belong in its final response.

Inspect the worker result and change set, including actual Serena use or its concrete fallback reason for supported code work. Resolve conflicts in the attached checkout, run focused validation, then obtain independent acceptance. Classify findings before assigning bounded corrections under shared recovery; preserve correction history and still-valid checks. Use Git and GitHub for authorized delivery under the root publication boundary. Completion requires the requested result, applicable review and verification, and that authorized endpoint.
